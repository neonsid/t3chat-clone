02

Catalog and picker scope

The model catalog can describe more than the chat picker, but only synchronous text-chat models with a configured runtime are selectable in this release.

Keep for this release

  • Synchronous text and supported multimodal-input chat models.
  • OpenAI models that work through the existing direct Responses integration.
  • Google Gemini chat models through the direct Google adapter.
  • Other compatible chat models available through OpenRouter.
  • Image-generation entries may remain catalog metadata, but stay out of the chat picker.

Remove or exclude for now

  • Perplexity provider and all Perplexity references.
  • Video generation models.
  • Speech, TTS, transcription, and music models.
  • Realtime and live-session models.
  • Embedding models.
  • Deep-research, managed-agent, robotics, and other long-running agent models.
Add explicit catalog fields such as activity, inputModalities, and outputModalities. Do not infer picker eligibility from a provider name or a model-name substring.

04

Reasoning-effort contract

The app exposes only Instant, Low, Medium, and High. Never expose or silently map to xhigh, max, or minimal.

OpenAI model family Choices shown in app App default Instant sent as Catalog action
GPT-5.6 / Terra / Luna InstantLowMediumHigh Instant none Deduplicate aliases; do not list the same underlying model twice.
GPT-5.5 InstantLowMediumHigh Instant none Keep.
GPT-5.5 Pro MediumHigh High Unsupported Keep; selector must not show Instant or Low.
GPT-5.4 / Mini / Nano InstantLowMediumHigh Instant none Fix Mini/Nano: send none, never minimal.
GPT-5.4 Pro MediumHigh Medium Unsupported Keep; selector must not show Instant or Low.
GPT-5.3 Chat — — — Remove because it is deprecated.
Codex, Realtime, specialist models — — — Exclude under the agreed agent/realtime scope.
For every provider, the registry is authoritative: show only supported choices; use the model's explicit default when switching; omit reasoning parameters for non-reasoning models; and return 400 for a forged unsupported model/effort pair. A provider's high stays high—it is never promoted to xhigh or max.

Land this in reviewable slices. Preserve the OpenAI path first, then add one runtime at a time.

Phase 1

Clean and classify the catalog

Remove Perplexity and unsupported specialist entries. Add explicit activity/modality metadata, enforce unique IDs, and create a deterministic chat-eligibility filter.

Split registry metadata from server adapters

Define the runtime union and per-model reasoning profiles in browser-safe code. Move adapter creation, API-key access, and provider request translation into server-only modules.

Harden the direct OpenAI path

Keep @tanstack/ai-openai, preserve its current stream behavior, correct Instant mappings, and support current model IDs by updating the adapter package or extending its model type where required.

07

Verification and acceptance

Most coverage should be deterministic adapter-contract tests. Live tests remain opt-in because they consume provider quota.

✓ Automated contract tests

  • GPT-5.4 Mini/Nano Instant sends none, never minimal.
  • GPT Pro profiles reject unsupported Instant and Low requests.
  • xhigh, max, and minimal never appear in the UI.
  • Non-reasoning models omit provider reasoning parameters.
  • OpenRouter High remains High and is never promoted.
  • A forged unsupported model/effort pair returns 400.
  • Switching models applies the new model's explicit default.

✓ End-to-end behavior

  • One mocked streaming regression test for each runtime.
  • One opt-in live smoke test for OpenAI, Google, and OpenRouter.
  • Existing OpenAI SSE deltas, finish state, and persistence remain unchanged.
  • Provider rail shows only providers with at least one executable chat model.
  • Removed models and Perplexity cannot be selected through UI or a forged request.
  • Stale saved model IDs fall back to a valid default without breaking chat load.

Risks and mitigations

The main risk is capability drift between catalog metadata, provider APIs, and adapter package types.

Risk
Severity
Mitigation
Catalog says a model is selectable but its runtime cannot execute it.
HIGH
Build the picker from the catalog intersected with the executable registry; assert every entry at test time.
Reasoning controls differ across model families and change over time.
HIGH
Keep an explicit per-model profile, validate on both client and server, and cover translation with contract tests.
TanStack adapter model unions lag behind newly released model IDs.
MED
Update compatible adapter versions first; otherwise use the adapter extension API instead of weakening types globally.
A missing credential blocks unrelated providers.
MED
Resolve the model runtime before checking its key and return a provider-specific configuration error.
OpenRouter model availability or capabilities drift from the local catalog.
MED
Keep a reviewed local allowlist, add catalog invariants, and periodically compare it with the OpenRouter Models API.
